## 📚 New Data Model Summary

### Core Architecture
```
organizations (tenant)
    ↓
org_members (junction)
    ↓ userId
users (identity only)

org_members → providerId (for PROVIDER_USER role)
    ↓
providers

clients (nested PHI: identity, contact, clinical)
    ↓
service_relationships (enhanced with flags, reasons)
    ↓
authorizations (funding lifecycle)
    ↓
actions (simplified 4 types)
```

### 4 User Roles (in org_members)
1. **ORG_ADMIN** - Full organization access
2. **SUPERVISOR** - Team-level access
3. **CASE_MANAGER** - Client caseload management
4. **PROVIDER_USER** - Provider agency user (linked to providerId)

### 5-State Service Relationship Lifecycle
```
REFERRAL_SENT → PENDING_START → ACTIVE ⟷ PAUSED → CLOSED
```

### 4 Simplified Action Types
1. **REQUEST_INTAKE** - Scheduling intake appointments
2. **REQUEST_UPDATE** - Status/progress updates
3. **REQUEST_DOCUMENT** - Documentation requests
4. **GENERAL_MESSAGE** - General communication

### Authorization Lifecycle
```
DRAFT → SUBMITTED → APPROVED / DENIED → EXPIRED
```
